# Лабораторна робота 4. Файли та надійне збереження даних

Мова: C, середовище: Linux.

## Мета

Побачити на власних файлах, як ОС зберігає їх і хто має до них доступ:

- що таке inode і чим ім'я файлу відрізняється від самого файлу;
- як працюють жорсткі й символьні посилання;
- як ядро вирішує, чи може процес читати, писати або видаляти файл;
- як замінити вміст файлу так, щоб збій у будь-який момент не залишив його порожнім або недописаним.

Теорія — підручник OSTEP (Operating Systems: Three Easy Pieces), розділи вказано в кожній частині.

## Середовище

Та сама Linux-VM, що й у попередніх лабораторних.

**Працюйте в домашньому каталозі всередині VM, а не в спільному каталозі з вашим комп'ютером.** Спільний каталог Vagrant (`/vagrant`) і подібні каталоги інших гіпервізорів — не звичайна Linux-ФС: жорсткі посилання, права доступу і `fsync` там працюють інакше або не працюють зовсім. Якщо в ЛР2 ви користувалися Vagrant, покладіть `lab4` усередину каталогу `lab2` на своєму комп'ютері: у VM він з'явиться як `/vagrant/lab4`. Звідти скопіюйте його в домашній каталог:

```sh
cp -r /vagrant/lab4 ~/lab4
cd ~/lab4
```

Підготуйте користувачів для частини 2 (скрипт створює групу `team`, користувачів `alice`, `bob`, `carol` і каталог `/srv/lab4`):

```sh
sudo sh setup-users.sh
```

Перевірка:

```sh
sh check_env.sh
```

Останній рядок має бути `Усе готово.`; якщо ні — у рядках `FAIL`/`MISSING` написано, що зробити.

## Довідка: файли в C

| Що                                          | Як                                                      |
| ------------------------------------------- | ------------------------------------------------------- |
| Відкрити файл                               | `open(path, flags, mode)`: повертає дескриптор або -1   |
| Записати `n` байтів                         | `write(fd, buf, n)`: повертає, скільки записано, або -1 |
| Дочекатися, поки дані файлу будуть на диску | `fsync(fd)`                                             |
| Закрити дескриптор                          | `close(fd)`                                             |
| Перейменувати (замінити, якщо `new` існує)  | `rename(old, new)`                                      |
| Видалити ім'я                               | `unlink(path)`                                          |

- `flags` поєднуються через `|`: `O_WRONLY | O_CREAT | O_TRUNC` — відкрити для запису, створити, якщо немає, і обрізати до нуля; `O_RDONLY | O_DIRECTORY` — відкрити каталог, щоб зробити йому `fsync`.
- Усі ці виклики при помилці повертають -1 і записують причину в `errno`; `perror("назва")` друкує її текстом. `perror` треба викликати одразу: наступний виклик може змінити `errno`.
- `ssize_t` — знаковий розмір: `write` повертає або кількість байтів, або -1.
- `mode`, наприклад `0666`, — вісімкове число (початковий `0`): права для нового файлу, з яких ядро ще прибере біти `umask`.
- Довідка: `man 2 open`, `man 2 write`, `man 2 fsync`, `man 2 rename`, `man 2 unlink`, `man 1 stat`, `man 1 chmod`.
